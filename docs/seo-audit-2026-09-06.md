# inklet 网站 SEO 检查

检查日期：2026-09-06。范围为线上 sitemap 中的全部 14 个页面、robots.txt、sitemap.xml、RSS，以及对应源码和本地生产构建。此次改动尚未部署。

## 搜索截图里的短横杠

`—` 不是 SEO 错误，换成 `-` 是更紧凑的排版选择。实际需要改善的是标题过长、被截断。Google 建议标题简洁、准确，并列举了短横杠、冒号和竖线等分隔符，没有把某一种分隔符规定为排名优势。见 [Google 标题指南](https://developers.google.com/search/docs/appearance/title-link)。

首页标题现为：

> inklet - Ambient E-Ink Displays for Your Second Brain

页面正文的大标题保持原样。所有搜索标题统一使用短横杠，并精简产品页和较长文章的搜索标题；文章正文标题及 URL 不变。

## 本次已修正

| 问题 | 证据与改动 |
| --- | --- |
| 主域名信号冲突 | 线上 `https://iminklet.com` 返回 307，跳转到 `https://www.iminklet.com/`，后者返回 200；原 canonical、sitemap、robots 和结构化数据都指向非 www。现在统一到实际服务的 www 主域，集中配置于 `src/lib/site.ts`。 |
| 站点名称不一致、分享标签缺失 | 原 WebSite 使用 `inklet LLC`，正文品牌使用 `inklet`；除文章外，各页面覆盖 Open Graph 时丢失 `og:site_name` 和 `og:type`。统一为品牌名 `inklet`，Organization 另保留 `legalName: inklet LLC`，共享元数据函数为每页输出完整标签。 |
| 隐私页分享标题错误 | 原 Twitter 标签继承首页标题，现使用隐私页自己的标题和描述。 |
| 首页 FAQ 标记与正文不符 | 首页没有 FAQ 展示，却输出 FAQPage。移除该标记；Display 和 About 中实际展示的 FAQ 及其标记保留。 |
| 硬件错误标记为可预订 | 用户确认 Kickstarter 尚未开始。移除 D1 和 Hub 的 Offer、PreOrder、价格有效期，保留 Product 描述并补齐图片和产品 URL。价格摘要暂不申报；开售后应按真实交易条件恢复。页面价格未改。 |
| 商店混合商品标记 | 原商店把单品、套装、软件和 Hub 都输出为有报价的 Product。改为指向各产品页面的 ItemList；Portal 详情页也不再输出该页未展示的报价。 |
| 重复公司实体 | About 页面重复注入 Organization；现在使用全站统一的一份。文章发布者使用同一个实体 ID 和品牌名。 |
| sitemap 修改日期不真实 | 原普通页面每次构建都更新 `lastmod`；无可靠修改日期的页面现在省略此项。Journal 取最新文章日期，修正数组首项 8 月 26 日早于实际最新文章 9 月 1 日的问题。 |
| RSS 主域不一致 | RSS 页面链接和 feed URL 跟随 www 主域；已有文章 GUID 保持原值，避免订阅器将全部文章当成新文章。 |
| SDK schema 属性归属 | SDK 同时声明 SoftwareApplication 与 SoftwareSourceCode，使 `codeRepository` 和 `programmingLanguage` 有对应类型。 |

主域名信号应保持一致，见 [Google canonical 指南](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)。站点名由 Google 自动选取，WebSite 数据表达的是偏好，不能保证截图上方立即显示为 inklet，见 [站点名指南](https://developers.google.com/search/docs/appearance/site-names)。

结构化数据应对应用户可以看到的真实内容，见 [结构化数据指南](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)。硬件目前没有报价或评价标记，因此不满足商品富媒体摘要所需条件；不能为取得摘要而虚构报价或评分，见 [商品摘要要求](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)。

`lastmod` 应记录实际重要更新；无法可靠获得时可以省略。Google 不使用 sitemap 的 `priority` 和 `changefreq`，本次也去掉了这些字段。见 [Google sitemap 指南](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。

## 进一步建议，尚未修改

1. **部署平台重定向**：保持 www 为主域时，将 Vercel 上非 www 到 www 的 307 临时跳转调整为 301 或 308 永久跳转。当前仓库的 Next.js 配置没有设置这条跳转；本次没有修改部署平台。
2. **商店主标题**：`/store` 没有 H1。可以把现有商品主标题改为 H1，保持视觉样式，或设计一个清晰的商店标题。这是语义和可访问性改进，不意味着缺少 H1 就无法收录。
3. **页脚 Hub 链接**：`Compute Hub H1` 指向 `/store#hub`，但页面没有该 ID，也没有 hash 驱动的切换逻辑。建议指向 `/hub` 产品页，或明确实现跳转到对应商品选项。
4. **按搜索意图增加内容**：目前 Journal 主要是品牌故事与工程文章。可以增加真实使用教程，例如把 Notion/Obsidian 笔记放到 e-ink、展示 PDF、家庭日程屏，以及本地 Hub 与云端 Portal 的区别。这里是基于现有内容的编辑建议，未进行关键词搜索量研究，也未自动添加正文。
5. **性能测量**：首屏动画使用初始透明状态，可能使内容的视觉显示依赖 JavaScript；是否影响 LCP 需要测量。建议按移动端检查 PageSpeed Insights / Search Console 的 Core Web Vitals。本次未取得真实用户性能数据，不对性能分数作结论。
6. **上线后收录核对**：提交新的 www sitemap，检查首页、Display、Hub、Store 的 URL Inspection，确认 Google 选择的 canonical 与声明一致，再请求重抓。标题和站点名需要重新抓取处理，不会随代码修改立即变化。
